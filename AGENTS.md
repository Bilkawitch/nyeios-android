## 2. Механизм аутентификации и сессии

### 2.1 Точка входа и параметры запроса
- **URL авторизации:** `https://eios.gukolomna.ru/index.php?login=yes`
- **HTTP-метод:** `POST`
- **Content-Type:** `application/x-www-form-urlencoded`
- **Обязательные поля формы:**
  - `AUTH_FORM=Y`
  - `TYPE=AUTH`
  - `USER_LOGIN=<логин или email>`
  - `USER_PASSWORD=<пароль>`
  - `USER_REMEMBER=Y` (для сохранения длительной сессии)
  - `backurl=/eios/` (целевой адрес перенаправления после входа)

### 2.2 Жизненный цикл сессии и Cookie
1. **Успешный вход:**
   - Сервер возвращает `302 Found` с редиректом на `backurl`.
   - В заголовках `Set-Cookie` возвращается набор куки, из которых ключевыми являются:
     - `PHPSESSID` — идентификатор PHP-сессии (`HttpOnly`, `Path=/`).
     - `BITRIX_SM_UIDH` — **32-символьный хэш авторизации пользователя**. Является главным маркером успешной аутентификации. Если этот маркер не выставлен — сессия считается анонимной.
     - `BITRIX_SM_UIDL` — URL-encoded логин пользователя (например, `user%40example.com`).
     - `BITRIX_SM_GUEST_ID` — числовой ID гостя в системе веб-аналитики Битрикса.
     - `BITRIX_SM_LAST_VISIT` — временная метка последнего визита.
     - `BITRIX_SM_TIME_ZONE=-180` — часовой пояс (UTC+3, московское время).
     - `BITRIX_CONVERSION_CONTEXT_s1` — сериализованный контекст конверсий.
2. **Неверные учетные данные:**
   - Сервер возвращает HTTP `200 OK` (не 401/403!), содержащий ту же HTML-страницу авторизации.
   - В теле ответа присутствует текст ошибки `Неверный логин или пароль портала ЭИОС`.
   - Выставляется HTTP-заголовок `X-Bitrix-Ajax-Status: Authorize`.
   - Кука `BITRIX_SM_UIDH` **не выставляется**.
3. **Требование к обработке редиректов:**
   - Клиент обязан сохранять куки со всех промежуточных 302-ответов (например, через `CookieJar` с просмотром цепочки `priorResponse`). Потеря кук на промежуточном шаге приводит к разрыву сессии.

## 4. Структура HTML и парсинг данных

### 4.1 Расписание (`/eios/contacts/timetable/`)
- **Корневая таблица:** `<table class="schedule-table">`.
- **Дни недели:** извлекаются из заголовка `thead > tr > th[1..6]` («Понедельник», «Вторник», «Среда», «Четверг», «Пятница», «Суббота»).
- **Временные слоты (Пары):**
  - Первая колонка каждой строки `tbody > tr > td[0]` содержит текст времени (например, `08:30 - 10:00`, `10:15 - 11:45`, `12:15 - 13:45`, `14:00 - 15:30`, `15:45 - 17:15`, `17:30 - 19:00`).
- **Ячейки занятий:**
  - Внутри ячейки дня располагаются вложенные таблицы `<table class="schedule-cell">`.
  - Строка подгруппы: `<tr class="schedule-cell-subgroup">` содержит текст подгруппы (например, `1 подгруппа`).
  - Строки данных с 2 ячейками:
    - Правая ячейка (`td[1]`) содержит либо аудиторию (если есть цифры или ключевые слова `ДО`, `ДОТ`, `ЭОР`), либо тип занятия («Практика», «Лекция», «Лабораторная»).
    - Левая ячейка (`td[0]`) содержит название дисциплины (если справа аудитория) либо ФИО преподавателя (если справа тип занятия).

### 4.2 Живая лента (`/eios/contacts/personal/user/<id>/`)
- **Контейнеры постов:** селекторы `.feed-post-block` или `.log-entry`.
- **Идентификатор поста:** атрибут `id` (например, `blg-post-38666` или `BLOG_10416-39139`).
- **Автор:** элементы с классами `.feed-post-user-name`, `.user-name` или `.author`.
- **Целевая аудитория (Группа):** элемент `.feed-add-post-destination-new` или `.destination` (например, `23АН-о-41`).
- **Дата и время:** элементы `.feed-time` или `.feed-post-time` (форматы: `сегодня, 11:52`, `вчера, 10:53`, `09.09 10:01`).
- **Текст объявления:** `.feed-post-text` или `.feed-post-contentview` / `.feed-post-text-block-inner`.
- **Прикрепленные документы:** ссылки `<a>` с расширениями `.pdf`, `.docx`, `.doc`, `.xlsx` или путями `/files/element/historyget/`.

## 5. Архитектурные проблемы и причины экстремальной медлительности

В ходе профилирования и анализа сетевого взаимодействия были зафиксированы следующие критические узкие места официального сайта:

### 5.1 Чудовищный размер DOM и разметки
- Страница Живой ленты отдает монолитный HTML-документ размером **7.57 МБ** на один GET-запрос.
- Сервер генерирует сразу **114+ постов** со всеми вложенными комментариями, формами отправки и модальными окнами без постраничной серверной пагинации.
- Архаичная табличная верстка с глубиной вложенности **до 15–20 уровней**:
  ```
  html.bx-core -> body.template-bitrix24 -> table.bx-layout-table -> tbody -> tr ->
    td.bx-layout-cont -> table.bx-layout-inner-table -> tbody -> tr ->
      td.bx-layout-inner-inner-cont -> div#workarea -> div#workarea-content ->
        div.workarea-content-paddings -> div#log_internal_container -> ...
  ```
  Это создает свыше 10 000 DOM-узлов, приводя к длительным фризам парсера браузера (Long Tasks > 1000 мс).

### 5.2 Избыточность ассетов (JS / CSS Bloat)
- На одну страницу подключается **42 отдельных CSS-файла** (стили ядра Битрикса, темы Intranet, UI-компоненты, стили задач, календаря, чата).
- Подключается **138 JavaScript-файлов**, большая часть которых выполняется синхронно в главном потоке (`core.min.js`, `core_ajax.min.js`, `sidepanel`, `intranet`, `socialnetwork`, `tasks` и CRM-модули).
- Зафиксировано более **800 событий Style/Layout Recalculation** при первичной загрузке страницы.

### 5.3 Отсутствие REST / JSON API
- На портале отсутствует публичный или внутренний легковесный JSON API для мобильных или сторонних клиентов.
- Любое действие (чтение расписания, проверка оценок, просмотр объявлений) требует вызова тяжелых монолитных серверных компонентов Битрикса (`bitrix:socialnetwork`, `bitrix:intranet`, `bitrix:main`), возвращающих гигабайты избыточного HTML.

### 5.4 Нестабильность под нагрузкой
- В пиковые утренние часы перед началом занятий (08:00–08:30) и в период экзаменационных сессий сервер под управлением PHP 7.2 исчерпывает пул воркеров (PHP-FPM) и возвращает ошибки `HTTP 504 Gateway Timeout` или обрывает соединения.
- Заголовки `Cache-Control: no-cache, no-store` форсируют полный пересчет страниц при каждом обновлении пользователями, вызывая лавинообразную нагрузку на базу данных MySQL.

## 6. Рекомендации для автоматизированных агентов и парсеров

1. **User-Agent:** Всегда передавать реалистичный заголовок `User-Agent` (например, браузерный Firefox или Chrome). Запросы с дефолтными заголовками утилит могут блокироваться WAF или веб-сервером.
2. **Таймауты:** Минимальный сетевой таймаут для запросов к `eios.gukolomna.ru` должен составлять не менее **10–12 секунд** из-за медлительности генерации страниц бэкендом.
3. **Хранение куки:** При выполнении логина сохранять куки со всех звеньев цепочки редиректов. Главным критерием валидности сессии является наличие непустой куки `BITRIX_SM_UIDH`.
4. **Кэширование на стороне клиента:** Любой внешний клиент обязан применять агрессивное локальное кэширование (SWR — Stale-While-Revalidate): сохранять расписание и посты ленты в локальную базу данных, чтобы не зависеть от частых падений университетского сервера.
